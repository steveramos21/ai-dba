Quick Start

Connect via URL

No config file needed

node dist/index.js repl
# connect mysql://user:***@host:3306/db

Config File

Multiple engines, persistent

cp config.yaml.example config.yaml
npm run repl

One-shot Command

Scriptable CLI for automation

node dist/index.js connect \
  'mysql://user:***@host:3306/db'

MCP Server

Connect AI agents to your databases

npm run serve

Installation

git clone <repo-url> ai-dba
cd ai-dba
npm install
npm run build

Configuration

Create config.yaml from the example:

cp config.yaml.example config.yaml

Connection URL (recommended)

engines:
  mysql-prod:
    type: mysql
    url: mysql://readonly:***@prod-db.internal:3306/app_db?ssl=true

The url field takes priority over individual fields. Supported URL params:

  • ssl=true — enable SSL with certificate verification
  • ssl={"rejectUnauthorized":false} — custom SSL options (JSON)
  • connectionLimit=10 — pool size (default: 5)

Individual fields (legacy)

engines:
  mysql-dev:
    type: mysql
    host: 127.0.0.1
    port: 3306
    user: root
    password: yourpassword
    database: yourdb
Security

config.yaml is in .gitignore by default. Never commit database credentials to version control.

connect

CLI

Connect to a database via URL and run diagnostics. No config file needed.

node dist/index.js connect 'mysql://root:***@127.0.0.1:3306/mydb'
node dist/index.js connect 'mysql://readonly:***@prod-db.internal:3306/app_db?ssl=true'

list-engines

CLI

List all configured database engines.

npm run list-engines

blocking-chains

CLI MCP MySQL

Detect and report row-level blocking chains using MySQL performance_schema.data_lock_waits.

Table output

npm run blocking-chains -- mysql-primary

JSON output

npm run blocking-chains -- mysql-primary -- --json
Requirements

MySQL 8.0+ with performance_schema enabled (default). If disabled, the tool returns an error telling you to enable it.

Auto SQL Detection

SQL keywords like SHOW DATABASES, SELECT * FROM users, DESCRIBE table_name are automatically routed to the sql command. No need to prefix with sql.

connect

Connect to a database via URL. No config file needed — the REPL starts with an empty engine list.

ai-dba[no-engine]> connect mysql://root:***@127.0.0.1:13306/testdb
Connected to 127.0.0.1-testdb
  mysql://root:***@127.0.0.1:13306/testdb

databases / db

Engine-Agnostic

List all databases on the connected server.

tables / dt

Engine-Agnostic

List tables in the current database with row counts, sizes, engines, and collations.

describe / desc

Engine-Agnostic

Show column details for a table — type, nullable, primary key, default value, auto-increment.

ai-dba[mysql-test]> describe users

indexes / idx

Engine-Agnostic

List indexes on a table — columns, uniqueness, primary key, index type.

ai-dba[mysql-test]> indexes users

processes / ps

Engine-Agnostic

Show active database connections — PID, user, host, database, command, time, state.

sql

Run a raw SQL query against the current engine. This is an engine-specific escape hatch — prefer the standard commands (databases, tables, etc.) when available.

ai-dba[mysql-test]> sql SHOW DATABASES
ai-dba[mysql-test]> SELECT * FROM users LIMIT 10

serve

MCP

Start the MCP server over stdio. Used by AI agents to call database diagnostics tools.

npm run serve

The server communicates via JSON-RPC over stdin/stdout. You typically don't run this directly — AI agents start it automatically.

MCP Agent Setup

Add AI-DBA to your AI agent's MCP server configuration.

Hermes

In ~/.hermes/config.yaml:

mcpServers:
  ai-dba-diagnostics:
    command: node
    args:
      - /path/to/ai-dba/dist/index.js
      - serve
      - --config
      - /path/to/ai-dba/config.yaml

Claude Desktop

In claude_desktop_config.json:

{
  "mcpServers": {
    "ai-dba-diagnostics": {
      "command": "node",
      "args": [
        "/path/to/ai-dba/dist/index.js",
        "serve",
        "--config",
        "/path/to/ai-dba/config.yaml"
      ]
    }
  }
}

MCP Tool: blocking-chains

The MCP server exposes one tool:

blocking-chains

Detect current row-level blocking chains on a MySQL database.

ParameterTypeRequiredDescription
engineIdstringYesEngine ID from config.yaml (e.g. mysql-primary)

Example MCP call:

{
  "method": "tools/call",
  "params": {
    "name": "blocking-chains",
    "arguments": {
      "engineId": "mysql-primary"
    }
  }
}

Response (no blocking):

{
  "content": [
    {
      "type": "text",
      "text": "No blocking chains found on engine \"mysql-primary\"."
    }
  ]
}

Response (blocking detected):

{
  "content": [
    {
      "type": "text",
      "text": "[{\"engine_id\":\"mysql-primary\",\"blocking_pid\":102,\"blocked_pid\":103,...}]"
    }
  ]
}

Docker Test Environment

A Docker Compose file is included for local testing with MySQL 8.0.

Start MySQL

docker compose up -d

Wait until healthy:

docker inspect --format='{{.State.Health.Status}}' ai-dba-mysql-test
# Repeat until "healthy"

Seed test data

docker exec ai-dba-mysql-test mysql -uroot -ptestpassword testdb \
  -e "CREATE TABLE IF NOT EXISTS blocking_test (
        id INT PRIMARY KEY AUTO_INCREMENT,
        name VARCHAR(100),
        value INT
      );
      INSERT IGNORE INTO blocking_test (name, value)
      VALUES ('alpha', 1), ('beta', 2), ('gamma', 3);"

Stop MySQL

docker compose down    # Stop containers
docker compose down -v # Stop and delete data

End-to-End Test

An automated test script creates a real blocking scenario and verifies detection:

node test/test-blocking.mjs

Expected output:

  1. Session 1 holds a row lock
  2. Session 2 is blocked waiting for the same row
  3. CLI detects and displays the blocking chain
  4. JSON output shows full chain details
  5. Cleanup — both sessions are released
Prerequisites

Docker MySQL must be running and seeded before running the test script. See Docker Environment above.

Architecture

src/
index.ts — CLI entry point (commander, REPL)
server.ts — MCP server setup, tool registration
config.ts — YAML config loader with URL parsing
connector.ts — DatabaseConnector interface (engine-agnostic)
types.ts — Shared TypeScript types
connectors/
mysql.ts — MySQLConnector (implements DatabaseConnector)
tools/
blocking-chains.ts — MCP tool schema + handler

Design decisions

  • DatabaseConnector interface — standard commands (databases, tables, describe, indexes, processes, query) that work across engines. Add PostgreSQL or SQL Server by implementing the interface.
  • Connection URLs — Connect directly via mysql://user:***@host:port/db?ssl=true without a config file.
  • Lazy imports — MCP SDK and mysql2 are loaded dynamically. CLI commands like list-engines start instantly without loading database drivers.
  • Lazy connection pools — MySQL connections are created on first use, not at startup.
  • One tool per file — Adding a new tool means adding a new file and registering it in server.ts.
  • Raw data only — The tool returns blocking chain facts. AI agents provide recommendations.
  • isError: true — Standard MCP error pattern with human-readable messages.

Error Handling

ScenarioResponse
Unknown engine IDUnknown engine "x". Available: mysql-primary
Unsupported engine typeEngine "x" is type "postgres". Only MySQL is currently supported.
Config file not foundConfig file not found: /path/to/config.yaml
