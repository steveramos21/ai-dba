Quick Start

Connect via URL

No config file needed

node dist/index.js repl
# connect mysql://user:***@host:3306/db

Config File

Multiple engines, persistent

cp config.yaml.example config.yaml
npm run repl

One-shot CLI

Scriptable automation

node dist/index.js connect \
  'mysql://user:***@host:3306/db'

# PostgreSQL
node dist/index.js connect \
  'postgresql:***@host:5432/db'

MCP Server

For AI agents

npm run serve

Installation

git clone <repo-url> ai-dba
cd ai-dba
npm install
npm run build

Configuration

Create config.yaml from the example:

cp config.yaml.example config.yaml

Connection URL (recommended)

engines:
  mysql-prod:
    type: mysql
    url: mysql://readonly:***@prod-db.internal:3306/app_db?ssl=true

  postgres-prod:
    type: postgres
    url: postgresql:***@prod-db.internal:5432/app_db?sslmode=require

The url field takes priority over individual fields. MySQL supports additional URL params:

  • ssl=true — enable SSL with certificate verification
  • ssl={"rejectUnauthorized":false} — custom SSL options (JSON)
  • connectionLimit=10 — pool size (default: 5)

PostgreSQL URLs are passed directly to pg.Pool({ connectionString }), so any pg-supported parameter works (sslmode, connect_timeout, etc.).

Individual fields (legacy)

engines:
  mysql-dev:
    type: mysql
    host: 127.0.0.1
    port: 3306
    user: root
    password: yourpassword
    database: yourdb
Security

config.yaml is in .gitignore by default. Never commit database credentials to version control.

connect

CLI

Connect to a database via URL and open an interactive REPL. No config file needed. Supports mysql://, postgresql://, and postgres:// URL schemes.

# MySQL
npm run connect -- 'mysql://root:***@127.0.0.1:3306/mydb'

# PostgreSQL
npm run connect -- 'postgresql:***@127.0.0.1:5432/mydb'

# With --type override
npm run connect -- 'postgresql:***@host:5432/db' --type postgres

This connects, verifies the connection, then drops you into the REPL where you can run databases, tables, describe, indexes, processes, etc.

list-engines

CLI

List all configured database engines.

npm run list-engines

blocking-chains

CLI MCP MySQL PostgreSQL

Detect blocking chains across MySQL and PostgreSQL. MySQL uses INNODB_LOCK_WAITS + INNODB_TRX; PostgreSQL uses pg_blocking_pids() + pg_stat_activity.

# Table output
npm run blocking-chains -- mysql-primary

# JSON output
npm run blocking-chains -- mysql-primary -- --json
Requirements

MySQL 8.0+ with performance_schema enabled (default). PostgreSQL 12+ (no special configuration needed — pg_stat_activity is available by default).

sql

Run a raw SQL query against the current engine. This is an engine-specific escape hatch — prefer the standard commands when available.

ai-dba[mysql-test]> sql SHOW DATABASES
ai-dba[mysql-test]> SELECT * FROM users LIMIT 10
Auto SQL Detection

SQL keywords like SHOW DATABASES, SELECT * FROM users, DESCRIBE table_name are automatically routed to the sql command. No need to prefix with sql.

MCP Agent Setup

Add AI-DBA to your AI agent's MCP server configuration.

Hermes

In ~/.hermes/config.yaml:

mcpServers:
  ai-dba-diagnostics:
    command: node
    args:
      - /path/to/ai-dba/dist/index.js
      - serve
      - --config
      - /path/to/ai-dba/config.yaml

Claude Desktop

In claude_desktop_config.json:

{
  "mcpServers": {
    "ai-dba-diagnostics": {
      "command": "node",
      "args": [
        "/path/to/ai-dba/dist/index.js",
        "serve",
        "--config",
        "/path/to/ai-dba/config.yaml"
      ]
    }
  }
}

MCP Tool: blocking-chains

The MCP server exposes one tool:

blocking-chains

Detect current blocking chains on a MySQL or PostgreSQL database.

ParameterTypeRequiredDescription
engineIdstringYesEngine ID from config.yaml (e.g. mysql-primary)

Example MCP call:

{
  "method": "tools/call",
  "params": {
    "name": "blocking-chains",
    "arguments": {
      "engineId": "mysql-primary"
    }
  }
}

Docker Test Environment

A Docker Compose file is included for local testing with MySQL 8.0 and PostgreSQL 16.

Start databases

docker compose up -d

Wait until both are healthy:

docker inspect --format='{{.State.Health.Status}}' ai-dba-mysql-test
docker inspect --format='{{.State.Health.Status}}' ai-dba-postgres-test
# Repeat until "healthy"

Seed test data

docker exec ai-dba-mysql-test mysql -uroot -ptestpassword testdb \
  -e "CREATE TABLE IF NOT EXISTS blocking_test (
        id INT PRIMARY KEY AUTO_INCREMENT,
        name VARCHAR(100),
        value INT
      );
      INSERT IGNORE INTO blocking_test (name, value)
      VALUES ('alpha', 1), ('beta', 2), ('gamma', 3);"

Stop databases

docker compose down    # Stop containers
docker compose down -v # Stop and delete data

End-to-End Test

An automated test script creates a real blocking scenario and verifies detection:

node test/test-blocking.mjs

Expected output:

  1. Session 1 holds a row lock
  2. Session 2 is blocked waiting for the same row
  3. CLI detects and displays the blocking chain
  4. JSON output shows full chain details
  5. Cleanup — both sessions are released
Prerequisites

Docker MySQL must be running and seeded before running the test script. See Docker Environment above.

Architecture

src/
index.ts — CLI entry point (commander, REPL)
server.ts — MCP server setup, tool registration
config.ts — YAML config loader with URL parsing
connector.ts — DatabaseConnector interface + BlockingChain type (engine-agnostic)
types.ts — DELETED (consolidated into connector.ts)
connectors/
mysql.ts — MySQLConnector (implements DatabaseConnector)
postgres.ts — PostgreSQLConnector (implements DatabaseConnector)
tools/
blocking-chains.ts — MCP tool schema + handler (connector map dispatch)

Design decisions

  • DatabaseConnector interface — standard commands (databases, tables, describe, indexes, processes, query) that work across engines. MySQL and PostgreSQL are implemented; SQL Server, Oracle, and MongoDB are planned.
  • Connection URLs — Connect directly via mysql:// or postgresql:// URLs without a config file.
  • Lazy imports — MCP SDK, mysql2, and pg are loaded dynamically. CLI commands like list-engines start instantly without loading database drivers.
  • Lazy connection pools — Database connections are created on first use, not at startup.
  • One tool per file — Adding a new tool means adding a new file and registering it in server.ts.
  • Raw data only — The tool returns blocking chain facts. AI agents provide recommendations.
  • isError: true — Standard MCP error pattern with human-readable messages.

Error Handling

ScenarioResponse
Unknown engine IDUnknown engine "x". Available: mysql-primary
Unsupported engine typeConnector's getBlockingChains() method throws
Config file not foundConfig file not found: /path/to/config.yaml
performance_schema disabledperformance_schema is disabled on engine "x". Enable it with: SET GLOBAL performance_schema = ON;
Connection refusedConnection error on engine "x": ECONNREFUSED 127.0.0.1:3306
Requirements

Node.js 18+, MySQL 8.0+ (with performance_schema enabled), and/or PostgreSQL 12+.
